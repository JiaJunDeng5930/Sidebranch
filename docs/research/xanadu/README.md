# Xanadu 原设计研究与 Sidebranch 修正依据

研究日期：2026-09-19。起因是用户指出当前 UI 把颜色带做成了虚线，并要求先研究原设计及其细节，再处理项目。本轮不修改产品 UI。本文替代旧研究中未经逐项核实的视觉推断；各原型的事实、项目自己的要求和后续工程选择分开记录。

## 先纠正研究方法

“三维页面、旁读、可见连接”不足以构成对 Xanadu 的复现。需要同时理解连接的内容身份、范围形状、当前关联片段、阅读位置、导航动作和页面变换。现有实现和旧设计把部分关系主动简化成细线；通过性能测试不能证明这种简化符合原设计。

本次查阅作者论文、官方截图、演示说明及原始程序代码，并实际打开原图、抽查作者视频。Windows 演示包只做静态解包和阅读，没有运行。2014 浏览器演示当前仅显示标志，新版演示地址未加载成功，因此其交互事实依照原始源码或作者说明标注，不能声称已经实测。

详细证据分为：[语义与文献](semantics.md)、[XanaduSpace 的版本与操作](xanaduspace.md)、[OpenXanadu 的范围与桥带实现](openxanadu.md)、[实际视觉观察](visual-observations.md)、[当前项目差距](project-gaps.md)。引用源码行号对应研究日期取得的原文件；文中 `/tmp` 路径只是本机临时回查位置，远程出处及包内路径才是可重复取得的依据。

## 不把不同原型拼成一个不存在的界面

| 材料 | 在本项目研究中的用途 | 必须保留的边界 |
|---|---|---|
| 1965 示意图、后续 Xanalogical Structure / Transliterature 论文 | 内容身份、独立连接、范围和双向追踪等语义 | 图中的细线、虚线或双线是对应材料的表达，不能拿来替代实际三维原型的颜色带。规范中的设想不等于全部实现。 |
| 2007 XanaduSpace 1.0 与论文图示 | 三维文档、当前页／旁读页、范围连接面及 reading plane | 2007 网页说明的相机键位与后期演示包不完全相同。 |
| 后期 D9y Origins 演示包 | 精确核实连接步进、当前关联片段、固定阅读位置和当前页切换 | 包名为 2013，README 有 2012 修订标识；不能冒称全部是 1.0 行为。 |
| 2014 OpenXanadu | 字符范围、多边形桥带、来源条带、命中和定位细节 | 是浏览器中的另一种布局，当时主要展示 transclusion；不能把其等宽双文档模式当作 XanaduSpace 的三维布局。 |
| 2016 xanaviewer 作者说明 | 区分链接桥与来源显示，了解操作流程与原型限制 | 不能把该版本的蓝／橙语义倒灌进 2014；作者承认的布局问题不是要复刻的目标。 |

Sidebranch 的三维阅读参照应明确落在 XanaduSpace 的 reading plane；OpenXanadu 用来补充可查的字符范围和交互证据，不把两个原型混成一份像素规格。[原作者回顾](https://xanadu.com/xUniverse-D6)、[XanaduSpace 论文](https://www.xanadu.net/XanaduSpace/btf.htm)、[后期演示入口](https://xanadu.com/xuspViewer.html)。

## 连接是有范围的关系

XanaduSpace 的实际截图展示具有面积的连接面，接到正文中的范围，高亮、页面和连接共同处于空间中。不能将范围合成一个中心点，再把点连成曲线，便声称保留了这一设计。也不能先把线加粗，再凭空决定纸边端口或曲率。[论文图 2](https://www.xanadu.net/XanaduSpace/btf_files/fwDemoOrigins-panorama2.png)提供了直接对照。

![XanaduSpace 原始全景：文本范围与有面积的连接面](https://www.xanadu.net/XanaduSpace/btf_files/fwDemoOrigins-panorama2.png)

图源：Nelson 与 Smith，Back to the Future，图 2。原图用于核对设计，不是 Sidebranch 当前效果。

需要保留的细节包括：范围在行中开始和结束，跨行之后的形状，不同字号下两端占据不同高度，多个范围相互重叠，以及滚动、换行和空间变换之后仍对应同一内容。OpenXanadu 的[范围转换](https://xanadu.com/xanademos/Data/Transformer/TransclusionTransformer.js)和[桥带绘制](https://xanadu.com/xanademos/Views/TransclusionOverlayView.js)可以检查这些问题的具体处理，不能只看一张远景图。

连接的形状不能抹平语义。普通 link 表达评论、解释等关系；transclusion 表示保持身份的同一内容出现在不同上下文。相似文字、AI 回答或手工关联都不自动成为 transclusion。Sidebranch 现有 Connection 可以使用有范围的颜色带，但不能因此冒称已经实现共享内容身份与版本继承。[Xanalogical Structure](https://xanadu.com/XUarchive/ACMpiece/XuDation-D18.html)、[Transliterature 存档](https://web.archive.org/web/20130718151249/http:/transliterature.org/)。

配色也有版本依据：2007 论文说明深色带为 link、红色带为 transclusion；D9y README 描述灰／粉；2014 源码按文档对共享色调。不存在把这些规则任意混合的理由。项目自己的关系配色可以设计，但必须声明为适配，并同时说明未选中、选中、重叠和不可见端点的表现。

## 阅读位置和导航不能只剩“打开另一篇”

XanaduSpace 的近景有主次：当前页较大，旁读页较小但可读，其他文档仍提供周围上下文。作者图示中的页面不只有位置变化，还会改变尺度及形状，使相关文本进入适合阅读的位置。[reading plane 原图](https://www.xanadu.net/XanaduSpace/btf_files/xusp-LineOfFire.png)。

![XanaduSpace reading plane：较大的当前页、较小的旁读页与远处文档](https://www.xanadu.net/XanaduSpace/btf_files/xusp-LineOfFire.png)

图源：同文图 4。截图证明布局和比例差别，不提供所有动态交互的参数。

后期 D9y 的 README 与 `startup.py` 更进一步区分了当前文档和当前关联片段。`c/e` 沿当前页选择下一／上一处连接，将目标对齐到未画出的 Current Line；`s/f` 沿左右关系把旁读页变为当前页。源码会跳过没有关系的片段，到边界保留状态。这些动作与相机运动、连续滚动、历史返回分别有自己的含义。具体键位属于该演示版本，不是要求网页占用同样字母键。[官方演示包](https://xanadu.com/xuspD9y%2C2013)，包内 `ReadMe!-Directions,License.txt`、`Program/scripts/startup.py`。

因此，后续设计必须回答：用户现在沿哪一条关系读；两端文字怎样同时到达可读位置；怎样查看同一处的多条关系；怎样沿关系继续与恢复历史；转换过程中旧页、目标页和色带怎样保持可追踪。固定把相机归零、交换两个等宽槽位，只解决其中一部分。

## 必须逐项设计和验收的细节

以下是由证据与用户要求推导的工作项，不声称原型已经给出了全部现代网页答案。每项都需要确定动作前、动作中、动作后的可观察状态，再进入代码。

| 工作项 | 需要明确的细节与验收场景 |
|---|---|
| 字符范围 | 行中起止、跨行、跨段、不同字号、重叠范围；目标高亮不能扩成整段，也不能丢成中心点。 |
| 带面与正文 | 两端如何衔接、深度和遮挡如何处理；色带的命中区域不能阻断正文的原生选文。 |
| 颜色反馈 | 关系类别与选中状态分别怎样表达；多个同类关系交叉时怎样识别同一条。不能仅靠每段随机换色。 |
| 不可见端点 | 正文滚出视口、正文尚未挂载、文档处于外围是三种情况；保留范围身份并提供回到实际内容的办法。 |
| 当前页与旁读页 | 主次尺度、阅读位置和关联片段对齐；窄窗仍能读清，不能因缩小字号丢失基本可用性。 |
| 关系步进 | 同一文档的上一／下一关联位置、同一范围的多条关系、无下一条时的结果，与全文滚动分开。 |
| 沿关系继续与历史 | 切换当前文档时保留对应片段；历史返回恢复既有上下文，不与沿另一方向跟随混用。 |
| 转换过程 | 文档、范围高亮与色带一起变化；中途改变目标、继续输入、加载失败时不留下错接的带面。 |
| 相机 | 平移、旋转、缩放、恢复可读位置各有输入归属；选字和滚动正文不能误触相机。 |
| 周边折页 | 这是用户指定的适配：轻揭、标题可读、堆叠选择、翻到深处、离开后的收拢、键盘到达，都要有具体行为。 |
| 控件与悬停 | 2014 代码没有提供通用 hover 规范；不能声称随意增加的悬浮按钮来自 Xanadu。先定义用户意图及反馈，再确定必要控件。 |
| App 与窄屏 | 鼠标、键盘、触摸和 reduced motion 的等价操作；宿主导航与选文草稿同时发生时仍保护当前阅读。 |
| 性能 | 在最终范围几何、重叠和转换都成立后，测量长文、密集连接及连续输入。不能靠省略主要视觉语义来获得达标结果。 |

## 保留用户要求，说明适配来源

屏幕边缘折页、全体文档属于同一空间、无目录侧栏和总览开关、选文向 AI 提问、独立回答文档、统一文件访问及可定位修改，是本项目明确要求。它们不全是原始演示的功能，不能伪称来自原型，也不能因为旧演示只读而删除。

手机布局、浏览器原生选文、输入法、hover 时机、动画的精确时长、密集关系的现代选择方式，都需要在原设计约束下自行设计。当前研究没有找到一份横跨所有原型、完整规定这些细节的统一规范。未知项保持未知，项目选择写成项目选择。

## 后续修正顺序

先依据[项目差距表](project-gaps.md)重新形成范围连接、阅读位置与导航的统一设计；再确定鼠标／键盘／窄屏和异常状态的细节；最后实施并逐条对照验收。旧的“普通 link 为细线、转引为固定宽度薄带”不能继续作为依据。此前提出的“纸边端口加闭合 Bézier”也只是未经完整研究的候选，不是已经确定的方案。

本研究不把这些工作项标成已实现，也不把先前 62 项测试和帧率结果改写成“已符合 Xanadu 设计”。产品代码仍保持研究开始时的状态。
