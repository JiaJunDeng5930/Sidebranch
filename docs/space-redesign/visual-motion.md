# Xanadu Sidebranch v3：视觉与动态契约

> 2026-09-19 用户纠正：本文件将普通 link 简化为细线、transclusion 简化为固定宽度薄带的规则不再作为实现依据。颜色带、正文范围、阅读尺度与导航细节需要依据 [原设计研究](../research/xanadu/README.md)重新设计；本文件保留已有方案记录，不代表已经符合 XanaduSpace。

## 1. 设计目标

视觉层的任务不是把文档做成几张漂浮卡片，而是让阅读者持续感觉到：自己正在一张可读纸面上，相关文字在邻近纸面上，无论纸面退到边缘还是暂未载入，文档都仍属于同一空间。

推荐的视觉命题是 **“暗室中的连续纸场”**：舞台保持安静、低反射；正文纸面明亮但不刺眼；深度由遮挡、边缘、比例、清晰度和有限阴影共同表达；关系色只出现在文字锚点、连接线和与该关系直接相连的提示上。当前文档靠位置、尺寸和完整可读性成为注意力中心，不靠整张纸染色。

这套设计优先保护三件事：

1. 正文必须先于空间效果被看见、选择和连续滚动。
2. 当前、近邻和外围文档必须一眼可分，但同一文档在迁移时不能像被销毁后重新创建。
3. 动画必须解释状态变化；任何输入都可以中断动画，且中断后界面仍对应一个确定的阅读状态。

本文件只规定可见层级、纸页与折边、色彩、字体、悬停和过渡。它消费空间模型提供的 `current / companion / return-leaf / peripheral / stack`、关系类型、内容就绪状态和稳定身份；不定义文档排序、导航历史、激活手势或数据加载策略。

## 2. 视觉层级：让阅读面保持安静

### 2.1 五个感知层

| 层级     | 用户感知                 | 必须可见的内容                                         | 视觉处理                                                        |
| -------- | ------------------------ | ------------------------------------------------------ | --------------------------------------------------------------- |
| 当前纸页 | 正在读的正文             | 正文、标题、版本、当前锚点                             | 正面、最大、最清晰；纸色与正文对比最高；阴影最短而清楚          |
| 近邻纸页 | 可以并读的相关正文       | 正文或目标摘录、标题、版本、关系                       | 最多一个；略小、轻微侧转或后退；仍满足正文对比与字号要求        |
| 返回叶   | 刚才从哪里读来、怎样返回 | 前一 current 的标题、版本、原 passage 摘录和“返回”语义 | 固定在 current 近侧的短叶；比普通外围叶展开更多，但不挂完整正文 |
| 外围纸页 | 空间中仍存在的文档       | 至少标题、版本/类型提示、关系数量或关系标签            | 退到边缘成为纸边或折页；不渲染成关闭按钮或目录行                |
| 叠页     | 多个文档共享一个边缘区域 | 栈名或中性计数、最前一页标题；展开后各页标题           | 最多 3 条真实错位纸边 + 数量；数量再多也不增加装饰层数          |

“未知/尚未加载关系”不形成第五种距离，也不显示成灰色远方纸页。只有已知属于空间的文档可获得纸边；关系数据未到时用局部的内容状态反馈，不根据未知数据移动纸页。

### 2.2 注意力不依赖整页颜色

- 当前纸页：完整纸面、正面姿态、正文锐度 100%、不透明度 100%。顶部不放“当前”大徽章；可在标题元数据中保留一个短的“当前”可访问文本。
- 近邻纸页：正文仍用同一墨色，只通过 4–8% 的亮度差、尺度和空间姿态退后。不得降低正文 opacity，因为透明文字会损失对比且看起来不可用。
- 返回叶：使用中性深色内侧边和明确的“返回到〈标题〉”文字，不借关系色冒充连接。若 A/B 确有连接，可另画真实 beam；返回语义本身不生成 beam。
- 外围纸页：正文不出现；纸边与标题的可见度可下降，但标题不得低于 4.5:1。只有纯装饰的后层纸边可以降到更低对比。
- 悬停或键盘聚焦：只提亮被指向的纸边、锚点和相连路径。不要同时提亮整个关系网络。
- 非活动关系：保留可见轮廓，不用 `display: none`。在拥挤处可以抽稀标签，但不能用透明度暗示关系不存在。

## 3. 纸页、纸边与折角

### 3.1 可读纸页

纸面使用暖中性的实色，而非仿旧纹理：

- `paper-current: #F3F0E8`
- `paper-near: #ECE9E1`
- `paper-edge: #D8D7D2`
- `paper-ink: #2B3036`
- `paper-muted: #666C72`
- `paper-rule: rgba(43, 48, 54, .18)`
- `stage: #151A20`
- `stage-raised: #1B222B`

纸面只允许极弱的亮度渐变（总差不超过 2%）来帮助辨认朝向，不使用噪点、纤维图片或高光扫过。正文下方不能有玻璃、模糊或半透明效果。纸页圆角为 2–3px；更大的卡片圆角会破坏纸张感。

阴影只表达离舞台的距离：当前纸页用 `0 12px 32px rgba(0,0,0,.28)`，近邻用 `0 18px 44px rgba(0,0,0,.24)`；外围仅留 1px 接触阴影。迁移过程中阴影分段切换或保持固定，不逐帧动画大范围 blur，以免滚动时耗费合成资源。

### 3.2 外围纸边

外围文档不是缩小后的整张卡片，而是从视口边缘露出的纸边：

- 静止时露出 30–42px 深度和至少 72px 长度。
- 标题保持横排。左右边缘的标题放在向内展开的短标签面上，不把汉字旋转 90°；上下边缘可直接横排。
- 单页在悬停或焦点进入后向场内展开到 152–220px，显示最多三行完整标题、版本和空间模型已选定的活动关系标签；没有活动关系时只显示已知关系数量。它仍是外围预览，不显示可滚正文。
- 长标题在静止态可省略，但展开态必须能读全：最多三行，超出时让标题区域自身滚动或提供完整文本的无障碍名称；禁止跑马灯。
- 纸边朝向空间内部的一侧保留 1px 暗边，明确它可以向内展开。关系色只占这条边的 3px 短段，不给整页上色。

窄屏下，外围纸边变为当前/近邻纸页之后的横向叠页带。它仍显示纸边、标题和关系提示，不退化成侧栏或汉堡菜单。

### 3.3 折角是操作线索，不是装饰

折角只用于外围纸边和叠页最前一页，位置始终在朝向场内的角。推荐尺寸：静止 14px，展开 18px；折面比纸面暗 8–10%，折缝 1px。折角的三层含义固定：

1. 有折角：此处是可以展开的文档纸页。
2. 折角后有错位纸边：此处是多文档叠页。
3. 关系色短线：该纸页与当前活动关系的类型；没有活动关系时使用中性刻度，未知关系不参与绘制。

折角不得承载“已读”“收藏”“关闭”或版本状态，也不能单独成为只有 14px 的命中目标。整个露出的纸边都是同一命中面，最小可操作区域由手势规范保证至少 44×44px。

### 3.4 叠页拥挤

同一区域无论包含 4 份还是 100 份文档，最多画三层纸边：最前一页为真实可聚焦对象，其后两层只表达“还有内容”。显示明确数量，如“其余 96”。关系色不能把每层染成彩虹；最前一页显示当前关系色，栈的其余关系用一条中性分段刻度表达，展开后再给每页自己的标签。

栈展开时以同一锚边为轴向场内扇开，桌面同一窗口最多显示 7 张短叶。根纸边始终留在原位，叶片沿浅弧线错位 18–28px、角度逐张相差约 3–6°，每张至少露出一段可读标题和完整焦点环；不能排成等宽、等距的纵向菜单。展开占用场内空白，不推动或遮住 current 的主要阅读列。翻到下一成员窗口时，根和扇形边界不动，只替换叶片内容。

窄屏一次最多显示 3 张短叶，在 current/companion 之后的专用纸场中沿浅对角线重叠；根、数量、当前窗口范围和前后翻动入口持续可见。它不能变成全宽列表或抽屉。此展开只揭示可选对象，不自动改变当前文档；选择短叶先形成 preview/companion，明确 promote 后才改变 current。栈折回后，最后被指向的纸页成为最前一页，以便视觉连续。

### 3.5 返回叶的连续性

A 提升 B 为 current 后，A 从完整阅读面收成固定返回叶，保留 A 的标题、不可变版本和原 passage 的 2–3 行摘录。返回叶建议露出 112–180px，不进入普通外围排序或 overflow stack；它和 B 的 current 同时可见，直到历史上下文改变。提升动画必须让 A 的纸面连续收拢到这张叶，而不是先淡出再生成一个新控件。

返回叶用中性“返回”标签和朝向旧阅读面的折边表达导航来源。它不是关闭按钮、面包屑或关系类型。键盘焦点和触摸激活都能取得完整标题；Back 恢复时，同一叶从当前 pose 展开回完整阅读面。

## 4. 颜色语义

### 4.1 关系颜色使用成对 token

同一关系在浅纸面与暗舞台上使用同色相、不同明度的 token。这样锚点文字和舞台上的连接线都能达到足够对比，而不是勉强复用一个颜色。

| 关系                | 纸面 `ink` | 舞台 `beam` | 辅助文字 |
| ------------------- | ---------- | ----------- | -------- |
| 引用 `reference`    | `#9A5C1F`  | `#D5A05C`   | 引用     |
| 解释 `explanation`  | `#1F716D`  | `#6CB8B1`   | 解释     |
| 提问 `question`     | `#73548C`  | `#B891CF`   | 提问     |
| 对照 `contrast`     | `#A23D3D`  | `#E07A70`   | 对照     |
| 延伸 `continuation` | `#5C6E24`  | `#A4B36D`   | 延伸     |

纸面 token 对 `#F3F0E8` 的对比度均约为 4.7:1 或更高；舞台 token 对 `#151A20` 均约为 6:1 或更高。实现前仍须在真实字号、抗锯齿和显示器上复核。

颜色永远不是唯一编码：每条可操作连接在聚焦或选中时显示关系文字；颜色辨识困难时，用户仍能从标签、端点形状和连接种类辨认。五种普通 link 都使用单线，避免给每种关系再分配复杂线型。

### 4.2 link 与 transclusion

- 普通 link：单条 1.5px 关系色线；活动时 2.5px，并在中点或不遮字的位置出现关系标签。端点为短圆帽。
- 有来源身份的 transclusion：两条相距 3px 的窄平行线或一条带内缝的 5px 薄带；来源端是开口方括号，使用端是闭口方括号，并标“来源”。关系色只做薄带中央细线，连接种类靠结构区分。
- 没有 source identity 时一律按普通 link 显示，不能因文本相似而出现双线、来源标记或“引用原文”文字。

### 4.3 文字上的锚点、焦点和选区

三类状态不能混成同一种黄色高亮：

- **持久关系锚点**：关系色 2px 下划线 + 8–12% 同色底。多条关系重叠时只画一层淡底，底部用最多三条 2px 分段下划线；更多关系显示“+N”标记，避免文字被彩条淹没。
- **导航焦点**（搜索命中、follow 到达的范围）：中性的 `#D6B36A` 16% 底色，加左右各 2px 的深色短括号；停留 1.5s 后底色降到 8%，括号保留至焦点改变。它不冒充关系色。
- **原生选区**：`#B8D7EE` 55% 底、正文墨色不变。用户正在拖选时，关系锚点底色降到 4%，但下划线保留，保证原生选区边界最清楚。
- **悬停关系**：锚点底色升到 20%，对应 beam 升到活动线宽；不改变浏览器选区。

当前纸页不使用强调色边框。键盘焦点环统一为 `2px solid #E7B879`，外偏移 3px；在纸面控件上改用 `#7A4B1D`，以保证对比。

### 4.4 状态颜色保留区

错误、保存、加载等系统状态不能借用五种关系色作唯一含义。错误使用图标 + 文本 + `#B83C45`；完成状态使用文本/勾形与中性深绿；加载以中性墨色进度反馈。问题实体本身也不因为 `question` 关系为紫色；只有明确的 `question` link 才使用该关系色。

### 4.5 版本、预览与新回答

- 历史 revision 保持和当前版同样清晰的纸面与正文，不做发黄、破损或低 opacity。标题元数据固定写成 `vN · 历史版本`，并用一条中性双细线区分；这能表达身份而不暗示内容失效。
- 临时 preview 是 2–4 行摘录的小纸签或短叶；companion 是可独立滚动、选择的完整纸面。两者不能只靠尺寸差区分，preview 顶部明确写“预览”，companion 的纸页身份区写“旁读”。
- 新回答使用中性深绿 `#2E6B4F` 的勾形/圆点加“新回答”文字；暗舞台对应 `#77C79A`。只有文字和图形一起出现，不能只靠绿点。答案抵达不让整张纸闪烁，也不使用 `question` 关系的紫色，避免把实体状态误解成 connection。
- archived 只在身份行显示“已归档”，纸面仍可读；除非领域状态确实禁止某动作，否则不降低整页 opacity。

## 5. 字体与连续阅读

### 5.1 字体策略

第一阶段不依赖远程字体，避免纸页出现字体闪动或字宽改变后连接端点跳动。

- 正文：`ui-serif, "Iowan Old Style", "Source Han Serif SC", "Noto Serif CJK SC", "Songti SC", STSong, serif`。
- 标题和界面：`Inter, ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Noto Sans CJK SC", sans-serif`。
- 版本、路径和偏移：`ui-monospace, "SFMono-Regular", Consolas, monospace`，并启用 `font-variant-numeric: tabular-nums`。

若以后内置字体文件，必须同时提供中西文覆盖、`font-display: swap`、metric override，并在字体替换后批量重测锚点几何；不能只换英文字体，让中文落回度量差异很大的系统字体。

### 5.2 阅读尺寸

| 元素              |             桌面 |  390px 窄屏 | 说明                           |
| ----------------- | ---------------: | ----------: | ------------------------------ |
| 正文              |      17px / 1.78 | 16px / 1.72 | 用户浏览器放大到 200% 仍不裁切 |
| 一级文内标题      |      28px / 1.35 |  24px / 1.4 | 不使用全大写                   |
| 二级文内标题      |      22px / 1.45 | 20px / 1.45 | 与正文至少留 1.3em 上间距      |
| 纸页标题          | 15px / 1.35，600 | 15px / 1.35 | 最多两行，完整名可展开         |
| 关系标签/常用控件 |  13px / 1.3，600 |  14px / 1.3 | 不使用现有 9–10px 大写标签     |
| 次要元数据        |       12px / 1.4 |  12px / 1.4 | 只用于版本、计数、路径         |

正文行宽以 58–72 个拉丁字符为舒适区；中文为约 30–38 个全角字符。当前纸页内部左右留白桌面至少 44px，窄屏至少 20px。段间距为 0.85–1em，列表和引用保持同一基线节奏。文内链接保留下划线，不只靠关系色。

代码块使用 14px/1.65，横向滚动发生在代码块自身，不能推动纸页或舞台。PDF/TXT/MD 进入统一阅读面后可以保留内容结构差异，但标题、元数据、选区与关系状态使用同一视觉语言。

### 5.3 标题与顶部边缘

纸页标题区是阅读定位，不是窗口标题栏：不做可拖拽手柄外观，不摆“关闭 ×”。当前纸页标题可在正文滚动后缩成 36–44px 的薄边，保留标题末级、版本和返回上下文所需提示；展开/折叠不得抢占正文滚动。

长标题默认两行，路径和版本放在独立元数据行，不与标题争抢一行。完整标题在标题获得焦点、悬停或被辅助技术读取时可取得；不得只依赖原生 `title` tooltip。

## 6. 悬停与预览

悬停只改变可见反馈和临时预览，永远不改变当前文档、历史、滚动位置或持久选择。触摸设备没有悬停等价物；相同信息必须能通过焦点或显式激活获得。

### 6.1 三阶段反馈

1. **指向（0–90ms）**：纸边/锚点出现焦点轮廓，光标和命中区稳定；不移动布局。
2. **意图成立（90–160ms）**：外围纸边向内展开标题；关系锚点提亮自身、beam 和远端锚点。这个延迟过滤穿越画面的偶然经过。
3. **停留预览（280ms 后）**：只有明确的关系锚点或 beam 才出现对端摘录预览。预览为 2–4 行，包含目标标题、版本、关系文字和真实摘录。若目标已是可读近邻纸页，则不再弹卡，只提亮近邻中的目标范围。

预览贴近触发端但不得盖住当前选区、同一行正文或连接端点；优先放在页边空白，空间不足时放到纸页外的舞台上。预览卡允许指针进入，形成从锚点到卡片的容错走廊；离开两者 120ms 后反向收起。键盘焦点下不设自动收起计时，直到焦点离开或用户取消。

### 6.2 外围与叠页悬停

- 外围单页悬停只展开标题、版本和关系摘要，不加载整篇正文，不建立新的近邻纸页。
- 叠页悬停只让最前叶轻微揭开，显示 stack 名称、真实/已知数量与最前叶标题；无论停留多久都不展开完整 fan。完整 fan 只响应空间/手势层给出的显式激活（如点击或 Enter），因此指针穿过边缘不会无意打开七张纸。
- 从一项滑向相邻项时，上一项立即开始 90ms 回缩，新项同步展开；不先全部折回再重新展开。
- 指针快速离开时从当前进度反向，不跳回静止帧。

### 6.3 选区优先

只要存在非折叠原生选区，正文上的悬停预览暂停，已经展开的关系预览在 80ms 内淡出，纸页不移动。选择浮层的位置以浏览器 range 的最终几何为准；拖选期间不追随每一个 `pointermove` 重排。用户清空选区后，悬停系统需重新满足 160/280ms 的意图阈值，不能立即弹回旧预览。

## 7. 动态语言

### 7.1 时长与曲线

| 变化                       |                  时长 | 曲线                         | 目的                              |
| -------------------------- | --------------------: | ---------------------------- | --------------------------------- |
| 颜色、细线、焦点环         |              90–120ms | `linear` 或 `ease-out`       | 用叠层 opacity 淡入，立即确认指向 |
| 外围纸边展开/折回          |             160/120ms | `cubic-bezier(.2,.8,.2,1)`   | 露出标题，不拖慢浏览              |
| 摘录预览出现/消失          |             140/100ms | `ease-out`                   | 保持正文位置稳定                  |
| 叠页扇开/合拢              |             220/160ms | `cubic-bezier(.2,.75,.25,1)` | 解释多页从同一栈展开              |
| current/companion 位置迁移 |             360–440ms | `cubic-bezier(.22,.78,.2,1)` | 让用户看见旧页去处和新页来向      |
| 导航焦点到达提示           | 180ms 入，1.5s 后降级 | `ease-out`                   | 确认落点，不持续闪烁              |
| 异步内容淡入               |                 120ms | `ease-out`                   | 避免整页突然跳变                  |

没有循环漂浮、呼吸、光带扫过或惯性摆动。纸页迁移只动画 `transform` 与必要的 `opacity`；正文排版完成后不做 scale 小于 0.96 的长时间阅读，以免文字发虚。最终落位必须使用 scale 1 的可读层。

颜色、线宽和焦点环的过渡应通过预先存在的两层样式做 opacity 交叉淡化，避免逐帧动画 `stroke-width`、边框和阴影。连接路径在端点变化时仍须按几何调度更新，但非活动装饰不因此触发布局读取。

### 7.2 注意力迁移的可见叙事

当空间层把 B 提升为当前时，视觉必须同时交代 B 的来处和 A 的去处：

1. 捕获 A、B 和可见 beam 的当前屏幕几何。
2. B 沿最短可读路径进入中央阅读位；A 同时退到空间模型指定的近邻或外围位置。两者在前 60% 时间内都保持标题可辨。
3. 与 A/B 相连的 beam 端点随纸面几何更新；路径可在 100ms 内交叉淡化，但不能留在旧位置再突然跳到新位置。
4. B 落位后才把正文锐度/细节层级提升为当前；焦点范围在最终几何稳定的下一帧显现。

不允许先淡掉 A、再凭空淡入 B，因为这会把连续空间重新变成页面切换。也不使用整场景 zoom-blur、翻页遮罩或白色闪屏。

### 7.3 内容尚未就绪

目标元数据已知而正文未到时，目标位置先出现稳定纸面：标题、版本和一条 2px 中性进度线。正文区域保留与预计阅读面一致的尺寸，可显示 3–5 条不闪动的排版骨架，但不伪造段落数量。连接线终点落在带“正文载入后定位”的纸边端点，不假装已经贴到具体文字。

内容到达后，真实排版一次替换骨架并在 120ms 内淡入；拿到实际 range 几何后端点从纸边移动到文字，180ms 完成。若请求对应的阅读上下文已经改变，内容可以进入缓存，但不得夺回当前、弹出纸页或重新播放旧动画。

失败时纸面留在原位置，正文区域显示一句可操作错误和重试入口；不让整张纸消失，也不把失败误画成文档不存在。

## 8. 中断契约

动画系统必须按“可重定向的连续状态”实现，而不是依赖一串不可撤销的完成回调。

### 8.1 新命令到来

- 每个活动过渡保存 `fromPose`、`toPose`、开始时间和语义 transition id。
- 新的空间命令到来时，读取当前合成后的可见 pose 作为新的 `fromPose`，直接改向新的 `toPose`；不得先跳到旧终点。
- 旧 transition 的完成回调必须凭 id 失效，不能在稍后把 current、焦点或 aria 状态改回去。
- 同一文档元素在迁移中保持稳定 key；标题和已加载正文不重新挂载，滚动位置因此保持。

### 8.2 用户输入中断

- 指针落到可读正文或开始选择时，所有会移动该纸面的过渡在当前 pose 暂停；已提交的 current/companion 语义不回滚。指针序列结束后，从冻结 pose 继续趋向该语义状态的终态。用户手下的文字不能继续漂移。
- 用户开始滚动某张纸时，该纸的装饰性展开/阴影过渡取消，但不会取消正文滚动或强制吸附回起点。
- 新的导航激活可以重定向旧迁移；`Escape`、失焦等取消动作的语义由 reading/gesture 契约决定，视觉层只负责从当前进度回到它们给出的目标状态。
- 浏览器标签页隐藏后不补播累计动画。恢复时直接采样语义状态并落到正确 pose。

### 8.3 指针离开和焦点切换

- hover 过渡从当前进度反向，禁止“展开一半 → 瞬间全开 → 再收起”。
- `pointerleave` 不能关闭仍含键盘焦点的预览；`blur` 也不能关闭指针仍在其中的预览。两者都离开后才收起。
- 焦点从锚点移到其预览或对应 beam 时视为同一 hover group，视觉保持。
- DOM 虚拟化要移除当前焦点元素时，先把焦点交给等价的纸边/关系标签，并给出可见焦点环，不能让焦点落到 `body`。

## 9. 窄屏、键盘与减少动态效果

### 9.1 390px 投影

窄屏保留纸页关系，但把深度投影为纵向阅读序列：当前纸页在前，活动近邻紧随其后，外围叠页带位于其后或贴近相关段落的间隔处。关系 beam 可缩成锚点旁的关系短线和连接标签；标签中保留关系文字与目标标题，激活后滚到近邻目标。不能仅保留颜色点。

纸页横向边距 12px，正文内边距至少 20px；标题和选择浮层不覆盖超过两行正文。外围横带每项至少 56px 高，折角保留在右上内向角。任何 3D 退化都不得移除版本、来源种类、关系标签或当前/近邻区分。

### 9.2 键盘等价

所有 hover 可见信息在 `:focus-visible` 下出现：纸边展开、完整标题、关系标签和摘录预览。键盘焦点不会因 280ms 停留计时自动弹出又消失；获得焦点即在 120ms 内显现，直到焦点移出其 group。

焦点顺序和 Enter/Escape 的动作由 gestures-performance 定义。视觉只要求焦点环始终不被纸页 overflow 或舞台裁切，且场景迁移结束后焦点仍附着于同一语义对象。

### 9.3 `prefers-reduced-motion`

减少动态效果时：

- current/companion、栈展开、纸边展开直接落到最终布局；不做空间插值、scale、旋转或视差。
- 允许不超过 80ms 的纯 opacity 状态确认；若系统要求完全禁用动画则为 0ms。
- beam 立即使用最终端点，不画路径生长。
- 导航焦点直接显示并保持，不做闪烁或脉冲。
- 所有语义和可见信息与完整动态模式一致。

## 10. 实现边界与性能友好做法

本视觉方案要求实现层遵守以下约束，但具体渲染路径由 gestures-performance 决定：

- 正文始终是真实可选择 DOM。纸面 transform 不触发正文重新排版。
- 只把正在移动的纸面提升到合成层；落位后撤销无必要的 `will-change`，避免为百份外围文档长期分配纹理。
- 关系线的颜色/粗细变化不读取布局；端点几何与相机变化按帧批量更新。
- 不动画大半径 `filter: blur()`、`backdrop-filter`、噪点遮罩或全场景 box-shadow。
- 外围纸边用简单矩形与折角伪元素表达，不挂载正文、Markdown renderer 或图片。
- 叠页的装饰层固定最多三层；100 份文档不会产生 100 个阴影。
- 骨架不使用循环 shimmer。它只是一组静态占位线和一条有界进度提示。

## 11. 跨组契约

### 11.1 视觉层需要的输入

| 来自                 | 必需输入                                                                                          | 原因                                                 |
| -------------------- | ------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| spatial-model        | 每份可见文档的稳定 id、角色、pose、边缘槽位、stack membership、已知/未知关系状态                  | 决定纸页是可读面、外围纸边还是叠页；视觉层不自行排序 |
| reading-flow         | current、active companion、active relation、focus range、selection、preview intent、loading/error | 决定强调状态和何时出现摘录，不自行改变导航           |
| gestures-performance | hover/focus group、输入所有权、transition interrupt/retarget 信号、reduced-motion、窄屏投影       | 确保动效不会与选择/滚动/相机争抢                     |
| domain               | relation kind、link/transclusion kind、source identity、revision/version                          | 保证颜色、线型和来源标记对应真实实体                 |

推荐共享的派生视觉状态（名字可由整合设计调整）：

```ts
type VisualRole =
  "current" | "companion" | "return-leaf" | "peripheral" | "stack";
type ContentReadiness = "metadata" | "loading" | "ready" | "error";
type Emphasis = "rest" | "hover" | "focus" | "active";

interface VisualDocumentState {
  documentId: string;
  revisionId: string;
  role: VisualRole;
  pose: { x: number; y: number; z: number; rotateY: number; scale: number };
  edgeSlot?: "top" | "right" | "bottom" | "left";
  stackId?: string;
  readiness: ContentReadiness;
  emphasis: Emphasis;
}

interface VisualConnectionState {
  id: string;
  relation:
    "reference" | "explanation" | "question" | "contrast" | "continuation";
  visualKind: "link" | "transclusion";
  emphasis: Emphasis;
  endpoints: "exact" | "clipped" | "paper-edge";
}
```

`endpoints: "paper-edge"` 必须带可见的“待定位”说明；不能与已取得文字 range 的 `exact` 画得完全一样。

### 11.2 视觉层不决定的事项

- 点击、Enter 或手势何时 follow/promote/back。
- 关闭近景是否回到历史、回到何处。
- 无关联文档、相同关系文档或百份文档的排序和聚合依据。
- 相机输入、滚轮归属、DOM 虚拟化阈值和数据分页大小。
- AI 排序、语义距离、来源身份或 revision 映射。

## 12. 验收观察

实现者应使用真实文档和真实操作观察，而不是只截静态图：

1. **连续迁移**：A 当前、B 近邻时提升 B；观察者能指出 A 去了哪里，迁移中两页标题均可辨，重复激活 C 能从中途平滑改向。
2. **选择不被抢走**：在关系锚点上慢拖跨三行选择；悬停摘录不弹出，纸面不移动，原生选区边界最明显。
3. **边缘发现**：不解释界面，让用户在 15 秒内找到一份外围文档并读出其完整长标题；他们不应把折角理解为关闭或收藏。
4. **百页叠放**：100 份同区文档仍只产生有限纸边；展开后标题可逐项聚焦，当前正文不移动，收起后保留最后指向项。
5. **关系辨认**：把画面转为灰度并模拟常见色觉缺陷，用户仍可借标签与线型区分关系文字以及 link/transclusion。
6. **异步中断**：follow B 尚未载入时立即转向 C；B 返回后不抢 current、不重播迁移，C 保持稳定。
7. **滚动中的安静**：连续滚动长文 30 秒，正文无透明、缩放模糊、循环光效或阴影抖动；关系线可更新但不遮挡选择。
8. **390px 与键盘**：不用指针完成查看完整标题、读取关系标签和抵达近邻摘录；视觉信息与桌面一致。
9. **减弱动态**：开启 `prefers-reduced-motion` 重做迁移与栈展开；无位移或缩放动画，最终层级和焦点仍完全可辨。

## 13. 需要原型验证的假设

以下是设计假设，不应在没有观察的情况下固化：

1. 30–42px 的外围露出量在 13–14 英寸屏幕上足够被发现，同时不侵占正文；需测试 1280×720、1440×900 和高 DPI。
2. 外围纸边展开到 152–220px 足以读三行中英文标题；需用最长真实标题和路径测试。
3. 160ms 的悬停意图、280ms 的摘录停留在高密度连接中不会误触或显得迟钝；需记录误展开次数与找到目标所需时间。
4. 五组关系色在项目目标显示器上既可辨又不抢正文；需做 WCAG 对比复核、灰度检查和色觉模拟。
5. 正文 serif 栈在 Windows、macOS、iOS 和 ChatGPT App WebView 的中文度量不会造成明显锚点跳动；需截取同一长文比较换行与 range 几何。
6. 360–440ms 的 current 迁移足以看懂来处/去处而不拖慢连续 follow；需让用户连续沿三条关系阅读并比较中断率。
7. 窄屏把 beam 化为锚旁关系标签后仍保留“同时可见关联文字”的感觉；需在 390px 验证 A/B 来回阅读，而不能只验证能点到。

这些验证失败时，优先调整尺寸、时长和排版密度；不要通过增加工具栏、目录或模式开关来补救可发现性。
