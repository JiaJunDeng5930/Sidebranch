# 阅读者端到端流程

本文定义阅读者从进入空间到连续阅读、提问、接收答案、查找、写作和回看版本时的意图与可观察反馈。它不规定文档在三维空间中的坐标、颜色、动画时长或具体输入映射；这些由空间、视觉和手势设计在本文语义上实现。

## 1. 设计目标与边界

阅读体验的主线是“当前文字仍在眼前，下一步内容在旁边抵达”。用户不需要先管理打开的窗口，也不需要在阅读与总览模式之间切换。所有文档一直属于空间；界面只改变注意力、局部呈现和读取深度。

以下原则贯穿所有流程：

1. **一次动作只表达一个意图。** 看一眼、沿连接旁读、把旁文设为当前、接收异步答案是四种不同动作，不能因为实现方便而都落成 `open_document` 后替换当前正文。
2. **当前文档不会被异步结果劫持。** 只有用户明确选择“设为当前”或执行搜索定位等根导航，当前文档才改变。
3. **精确来源始终可见。** 选区、问题、搜索命中、连接端点都带文档标题、不可变版本和精确文字范围；相似文字不当作原端点。
4. **短暂状态不污染历史。** 悬停、结果高亮、菜单和对话层不写导航历史；旁读、提升、搜索定位、打开指定版本会写入可返回的阅读上下文。
5. **写入与展示分阶段。** 问题保存、发送给 ChatGPT、答案文档创建、问题—答案关联、文字连接是不同结果，分别反馈，失败时只重试失败的阶段。
6. **主要阅读面不长期让位给管理界面。** 搜索、历史、归档、导入任务和编辑器按需出现，结束后回到原阅读上下文；不引入常驻目录或总览侧栏。

## 2. 阅读上下文和交互状态

实现应区分持久领域对象、可返回的阅读上下文和瞬时界面状态。

### 2.1 可返回的阅读上下文

一个历史条目至少保存：

- 当前文档的 `documentId + revisionId`、正文滚动位置和精确焦点；
- 正在旁读的文档（若有）的相同信息；
- 当前被检查的连接或问题；
- 空间设计要求恢复的局部呈现/镜头状态；
- 触发来源，例如连接、搜索命中、答案或历史版本。

“返回/前进”恢复整个上下文，而不只是文档 ID。恢复后用户应看见此前的当前/旁文角色、两边的滚动位置和精确段落。正文滚动本身不为每一像素制造历史条目；离开上下文或角色变化时保存最新位置。

### 2.2 不进入导航历史的瞬时状态

- 悬停或键盘聚焦产生的预览；
- 未提交的搜索查询及当前高亮结果；
- 选择工具、菜单、提示和错误消息；
- 尚未确认的创建连接第二端；
- 编辑器中仍未保存的本地草稿。

瞬时状态可以有自己的撤销/关闭规则，但不能让浏览器“返回”变成关闭一个气泡。

### 2.3 必须显式建模的异步状态

- 搜索：`idle | querying(query, requestId) | results | failed`；
- 问题：`draft | saving | saved | sending | awaiting | send_failed | answered`；
- 答案抵达：`unseen | seen | reading`，与回答文档身份分开；
- 导入项：每个文件独立的 `queued | importing | imported | failed`；
- 编辑：`clean | dirty | saving | conflict | failed`。

这些状态以请求 ID 和原始意图关联。晚到的旧搜索、旧打开请求或旧保存结果只能更新自己对应的任务，不能覆盖用户后来选择的当前文档、查询或草稿。

## 3. 四种容易混淆的阅读意图

这是跨组实现时必须保持的唯一语义。

| 意图               | 触发前提                                                       | 可观察结果                                                                                             | 是否改变当前文档 | 是否记入导航历史                     |
| ------------------ | -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ | ---------------- | ------------------------------------ |
| **悬停/聚焦预览**  | 指针停在折页、标题、连接标记或搜索结果上；键盘焦点落到相同对象 | 显示足以判断的标题、版本、关系、短摘录或目标段落预览；移开/失焦后消失                                  | 否               | 否                                   |
| **沿连接并读**     | 用户激活一条明确连接的“旁读”动作                               | 目标的**连接所指版本和段落**成为可滚动、可选择的旁文；原文仍是当前；连接持续可见                       | 否               | 是，返回可撤销这次旁读并恢复此前旁文 |
| **将旁文设为当前** | 用户在旁文上执行明确的“设为当前/继续读这篇”动作                | 旁文成为注意力中心；旧当前保留为旁文或空间中的可返回上下文，原滚动和焦点不丢失                         | 是               | 是                                   |
| **异步答案抵达**   | 已发送问题关联到一个独立回答文档；结果可能在用户阅读别处时返回 | 问题标记变为“已有回答”，出现非模态的新答案提示，并记录回答文档；不移动阅读面、不关闭选择、不抢键盘焦点 | 否               | 否；用户随后选择“旁读答案”时才写历史 |

补充约束：

- 悬停停留多久、预览在空间何处出现、触摸如何替代 hover，由手势和视觉方案决定；但预览永远不加载成可编辑的当前文档，也不改变滚动位置。
- 点击旁文正文首先意味着阅读、滚动或选择文字，不能暗中提升。提升使用标题/纸页身份区域上的明确动作，避免用户想选字时意外换主文。
- 一条文字上有多条连接时，第一次激活先给出可辨认的关系列表；选择其中一条后才旁读。列表按已有关系类型和稳定顺序显示，不依赖未来 AI 排序。
- “收起旁读”只改变当前阅读快照；不关闭文件、不删除文档或连接，也不等于归档。Back 忠实恢复前一阅读快照，因此可以重新出现当时的旁文；实现不为收起过的呈现实例维护 tombstone。

还有一种独立意图是 **AI 明确设为当前**：用户在对话中要求 AI 定位或打开某文档后，host 发来的普通 `open_document` 是已授权的根导航。它把指定文档和版本设为 current、写入阅读历史，并让返回恢复原上下文；它不是“答案自然抵达”。两者必须由调用意图或 `questionId` 归因区分，不能凭目标文档看起来像回答而猜测。

## 4. 连续阅读流程

### 4.1 进入空间

有可恢复会话时，恢复最后一个当前文档、版本、段落和旁读关系。恢复期间先显示文档身份和稳定的正文骨架；正文或关系分页未到达时标注“正在读取”，不能把未加载关系表现为“没有连接”。

没有会话但空间非空时，显示最近明确阅读的文档；“最近修改”只能作为没有阅读记录时的确定性后备。空间为空时，阅读面只给出“新建文档”和“导入文件”两个首要动作，并说明支持 TXT、Markdown 和带文字层的 PDF。

### 4.2 在当前文档中阅读

文档身份区持续提供标题、路径、版本和“历史版本”状态。正文是原生可选择文字。滚动只移动这份正文；相关文字标记与连接端点随正文更新。

连接标记在未激活时只说明“这里有关系”。预览回答“连到哪里、是什么关系、哪一个版本”；旁读才真正取回目标正文并定位到端点。目标尚未载入时，原文保持可用，目标位置显示局部加载状态。加载失败时保留原文和可重试动作。

### 4.3 从 A 沿连接读 B，再继续读 B

1. 用户在 A 的某段查看连接预览；A 不变。
2. 用户选择“旁读”。B 的连接所指不可变版本和段落进入旁读角色；A 仍为当前。
3. 用户可以独立滚动、选择 B 的文字，或从 B 再预览其它连接。此时 A/B 的滚动互不影响。
4. 用户明确选择“继续读 B”。B 成为当前，A 保留其版本、段落和滚动位置，作为旧当前/可返回关系。
5. 用户按返回，忠实恢复提升前的快照：A 为当前、B 为旁文，以及两边当时的版本、焦点和滚动。若之后曾“收起旁读”，Back 仍可恢复更早快照中的 B；收起不是关闭文件或永久排除对象。

若从 B 再沿连接读 C，在可读旁文容量有限时，新旁文替代此前的近景旁文，但被替代文档仍在空间且可由历史恢复。容量与折叠方式由空间设计决定，本文只要求每次替代可解释、可返回。

### 4.4 无连接文档的发现

无连接文档不能被等同于不存在，也不能用伪造的语义距离排列。它通过以下明确入口被发现：

- 全局搜索；
- 空间边缘文档身份的预览与激活（具体折叠由空间设计定义）；
- 创建/导入完成提示；
- 归档查看与恢复。

激活一个无关系文档是“根导航”：它成为当前，旧上下文进入返回历史；系统不画虚假连接，也不假装它与旧当前相关。

空间只把相对 current 已被索引证明的一跳、二跳关系当作关系图；未加载或无已知路径都只能称为“尚未证明关系”。其它文档保留在边缘 stack。展开 stack 只在场景内形成数量有界的 fan：第一次指向/聚焦某叶片只显示标题、版本和摘录预览；第二个明确的“设为当前”动作才执行根导航。fan 的第一击不能直接改变 current。A 沿关系提升 B 后，A 作为固定返回叶存在；Back 恢复 A 的原 revision、段落、滚动和当时的旁读快照。

## 5. 选区与提问

### 5.1 建立问题草稿

完成非空文本选择后，先出现紧贴选区的轻量动作层，至少包含“提问”和“连接文字”。动作层显示选区短摘录；长摘录折叠但提交仍携带完整 `revisionId/start/end/quote`。

选择“提问”后才展开问题编辑器。编辑器固定显示来源标题、`vN` 和摘录，正文输入获得焦点；原文选区保持标记。用户滚动或查看旁文时，编辑器可收成“问题草稿”提示而不丢文字。关闭未提交草稿时，如果已有输入，应保存在当前会话并给“继续编辑/丢弃”选择；页面意外重载后的持久草稿不是本轮必要能力。

### 5.2 提交分成保存与发送

提交必须按以下阶段反馈：

1. `saving`：保存 Question；按钮显示“正在保存”，防止重复提交。
2. `saved`：问题实体已存在，立即在来源段落出现问题标记。
3. App 中进入 `sending`，把已保存问题发送到当前 ChatGPT 对话；网站中明确说明“问题已保存”，可复制给 ChatGPT，不能假装已发送。
4. `awaiting`：显示“等待回答”，编辑器可关闭，阅读继续。

如果保存成功而发送失败，状态是“已保存，发送失败”，重试只发送同一个 `questionId`，不能再创建一份 Question。用户修改已经保存的问题文本时，需创建新的问题或明确重新提交；不能静默修改已发送问题的含义。

同时存在多个问题时，每个以 `questionId` 独立跟踪；界面不能用一个全局 `question` 草稿推断所有答案归属。

### 5.3 提问不会自动制造关系

保存问题不创建 Connection；回答出现也不自动证明某两段文字相连。ChatGPT 可以创建独立回答文档、通过 `answer` 把它关联到问题，再按实际内容显式 `link` 相关段落。界面分别显示：

- 问题是否已保存/发送；
- 是否已有回答文档；
- 回答与原文之间是否另有精确文字连接。

回答有关联但没有 Connection 时，仍可旁读整份回答，文案只能说“这个问题的回答”，不能画一条假装精确到段落的 beam。

## 6. 答案抵达与继续阅读

### 6.1 抵达协议

仅有 `open_document(answerDocumentId)` 不足以判断它是 AI 按用户要求明确设置 current，还是某个问题的异步回答。兼容规则是：**没有答案归因的普通 `open_document` 按“AI 明确设为当前”处理**；答案抵达需要 App/host 边界提供明确意图，至少包含：

```ts
type AnswerArrival = {
  questionId: QuestionId;
  answerDocumentId: DocumentId;
  answerRevisionId: RevisionId;
  connectionIds: ConnectionId[]; // 可以为空；只列已真实建立的连接
};
```

这可以作为 host UI 更新信封，也可以是有界只读投影；不能靠“最近打开的回答文档”或内容特征猜测。收到信封后，服务端必须核验 `questionId + answerDocumentId` 的 AnswerAssociation，核验通过才进入 `answer-arrived`。若协议暂未扩展，当前会话也只能用已发送的 `questionId` 和服务端关联核验后显示“回答”；无法核验时不触发答案抵达流程，普通 `open_document` 仍执行 AI 明确设为当前。

### 6.2 抵达时的可观察行为

- 问题标记从“等待回答”变为“已有回答”；全局活动入口增加一条未读记录。
- 使用 `aria-live="polite"` 宣布“某问题已有回答”，但焦点仍在用户当前操作处。
- 不改变 current，不滚动正文，不关闭搜索、编辑器、选区或另一条旁读关系。
- 若回答含真实 Connection，可显示对应关系入口；若没有，只显示问题—回答关联。
- 多个回答各自列出标题和版本，不用最后一个覆盖前一个。

提示提供两个明确动作：

- **旁读答案**：如果当前仍是问题来源上下文，在旁边呈现回答；如果用户已经离开，先恢复问题来源的阅读上下文，再把回答作为旁文。这是一次可返回导航。
- **稍后阅读**：只消除未读提醒，问题和回答关联仍保留；以后从来源问题标记或活动入口进入。

用户随后可明确把回答设为当前。即使 ChatGPT 最后调用了 `open_document`，只要调用被标记为该问题的答案抵达，Reader 也按以上规则处理，不能直接替换当前文档。相反，用户明确要求 AI 打开或定位文档产生的 `open_document` 应直接执行设为当前，不弹出多余确认。

### 6.3 AI 明确设为当前时保全进行中的操作

普通阅读状态下，AI 的明确 `open_document` 立即导航。但 host 结果可能恰好在用户操作中途返回，必须遵循以下保护：

- 指针仍按下进行选字，或输入法仍在 composition 中：等到 `pointerup/selectionchange` 稳定或 `compositionend` 后再导航；不截断半个选区或未上屏文字。
- 已形成普通选区且动作层打开：把精确 `revisionId/start/end/quote` 保存为来源书签，再导航；返回可恢复来源和选区焦点。浏览器 DOM selection 可以清除，但语义选区不能丢。
- 问题草稿已有文字：将草稿收成带来源标题和版本的会话草稿提示，再导航；回到来源可继续编辑。空草稿可以关闭。
- 正在选择 Connection 第二端：保留第一端并把连接流程收成提示；新 current 中可以继续选择第二端或返回，不能把新文档误当自动第二端。
- 创建或编辑器有 dirty 草稿：把导航记为待执行目标并提示“AI 已定位到 X”。编辑器仍保留焦点和全文；用户保存或关闭后自动执行。若选择“现在打开”，草稿先存入会话再导航，不丢内容。

这些保护只延后或收起界面，不否定用户已授权的 AI 导航。待执行目标若又被更晚的明确导航替代，只保留最新目标，并让用户看得见目标已变化。

### 6.4 乱序和失败

- 答案在 Question 保存完成前不会被 UI 接受为该问题答案；host 应等待持久 `questionId`。
- 回答文档已写入、`answer` 关联失败时，提示“回答文档已创建，尚未关联”，提供重试关联，不删除文档。
- 关联成功、`link` 失败时，仍显示回答，但明确“暂无文字连接”；重试连接不会重复关联。
- 用户已归档来源文档时，答案仍可抵达；查看时显示来源已归档，并允许只读回看或恢复。
- 旧请求的答案到达时根据 `questionId` 进入对应记录，不改变正在编辑的新问题。
- AI 明确设为当前的读取失败时，原 current 和进行中草稿保持原样；错误提示说明目标，允许重试，不留下半完成的历史条目。

## 7. 查找与定位

### 7.1 当前文档内查找

当前文档查找是轻量覆盖层，使用当前已取得的不可变版本内容进行字面匹配，显示“第 n / 共 m 处”。上一处/下一处只改变当前文档焦点和滚动，不创建全局导航历史；关闭查找后保留最后到达的位置。虚拟化正文必须把目标区块挂载并定位，不能依赖浏览器只搜索当前 DOM。

查找历史版本时只查该版本，并在结果旁持续显示 `vN · 历史版本`。

### 7.2 全空间搜索

全局搜索由搜索命令或快捷入口打开为覆盖层，空间留在背景中。初始状态显示最近查询或简短使用提示，不预先加载完整正文目录。

现有后端是标题、路径和当前正文的**区分大小写字面搜索**，界面必须如实说明这一点；不得把结果包装成语义搜索或 AI 相关度。结果包含：标题、路径、版本、命中摘录以及命中在标题/路径/正文的类型。正文命中使用服务端返回的精确 UTF-16 `start/end`。

查询行为：

- 输入变化采用短延迟并取消/忽略旧请求；结果可按页追加，不能等待全空间扫描完成才首显。
- 键盘或指针高亮结果只预览摘录，不改变空间。
- 激活正文命中会打开**搜索时返回的 revisionId**，将精确范围设为焦点并滚动定位。若此时已有新版本，历史标签和“查看最新版”动作同时出现，不把偏移套到最新版。
- 激活标题/路径命中打开结果版本的开头。
- 搜索定位是根导航并写历史；返回恢复搜索前完整阅读上下文。搜索查询可在返回后恢复，便于选择下一条。
- 无结果保留查询和作用域，给出“包括归档”或调整大小写等真实可执行的动作，不建议不存在的语义匹配。

### 7.3 归档搜索

默认全局搜索只覆盖活动文档；用户可显式打开“包括归档”。归档结果带固定状态标签。打开归档文档不会自动恢复它；只读阅读后可以另选“恢复到空间”。

## 8. 新建、导入和编辑

### 8.1 新建文档

从空间命令入口选择“新建文档”后出现专注写作层，包含标题、路径、格式和正文。原阅读上下文留在背景并冻结空间导航，草稿不会因误点背景消失。

保存成功后创建独立 Document 和 v1：

- 用户从非空空间发起时，显示“已创建”以及“设为当前”动作；默认回到原文，避免一次保存突然替换阅读对象。
- 用户在空空间创建第一份时，它自然成为当前。
- 若创建的目的来自“回答问题”，仍需显式 `answer` 关联；若来自连接流程，仍需选择第二端并确认 `link`。

路径冲突、大小超限或网络失败保留全部草稿与光标位置。用户修正后重试同一意图。

### 8.2 导入文件

导入器接受 TXT、Markdown、PDF，可多选。任务面板逐项显示文件名、目标路径、大小和状态；一个文件失败不回滚其它成功项。导入期间用户可以关闭任务面板继续阅读，活动入口保留进度。

成功项成为普通文档并保留原始文件资产。批量导入不轮流抢占 current；每项提供“查看”，只有空空间中的第一份成功导入可以自动成为当前。PDF 没有文字层时明确说明需要 OCR，不能导入成看似空白的成功文档。路径冲突允许编辑该项路径后单独重试。

### 8.3 编辑现有文档

从某一可读页面的身份菜单进入编辑。编辑器绑定开始编辑时的 `expectedRevisionId`，顶部持续显示“正在编辑 vN；保存将创建 vN+1”。历史版本只读；从历史版本选择编辑时，先提供“打开最新版后编辑”，不伪造分支能力。

保存成功后的推荐行为：

1. 同一页面切到新版本，保留可合理恢复的滚动位置；任何无法证明仍指向同一内容的精确焦点都清除。
2. 明示“已保存 vN+1”。
3. 旧连接仍指向 vN。若当前已载入的连接中有旧端点，提示“有 x 条连接仍指向 vN”，提供“查看旧端点”；绝不把它们迁移到相似文字。
4. 旧版本仍可从版本历史或连接端点读取。

并发冲突时进入 `conflict`：保留用户草稿，显示当前最新版的版本号，并提供“查看最新版”和“复制草稿”。只有用户重新核对后才可基于最新版再次保存；不自动重放整篇替换。普通网络失败保留编辑状态并允许重试。

重命名/移动只改变路径身份，成功后当前阅读位置不变；若路径冲突则保留输入。下载是当前正在看的特定版本，文件名和版本状态需明确。

## 9. 文档版本历史与归档

### 9.1 两种“历史”不能混淆

- 顶层返回/前进是**阅读历史**：恢复 current、旁文、焦点和滚动。
- 文档菜单中的“版本历史”是**内容历史**：列出该 Document 的不可变 revisions。

版本历史按版本号和时间显示，当前版明确标注。选择旧版本先在当前上下文中作为可读的版本预览/旁文出现；用户可再明确“以此版本为当前阅读版本”。打开旧版本会写阅读历史。旧版标题持续带 `vN · 历史版本`，且没有普通保存按钮。

当前数据不提供差异算法，因此本轮不承诺逐字 diff。若以后加入比较，它必须比较两个明确 revision，而非“旧/新”模糊引用。

### 9.2 归档

归档是可恢复的生命周期状态，不是删除：

- 归档当前文档后，它仍留在眼前并显示“已归档”；用户可以完成阅读、查看历史或立即恢复。离开后它退出默认活动空间呈现和默认搜索。
- 指向归档文档或其旧版本的 Connection 仍有效。沿连接到达时显示归档状态，但不要求先恢复。
- “归档”入口是按需覆盖层或搜索作用域，不是常驻文档侧栏。可按标题/路径查找并恢复。
- 恢复只改变归档状态，不建立新版本、不改变连接端点，也不自动设为当前。

执行归档前说明影响并允许撤销；不要求二次确认对话框，因为操作可逆。若归档写入失败，页面和空间归属保持原状态。

## 10. 中断、取消和焦点规则

### 10.1 用户意图优先于晚到结果

每个读取操作记录发起时的 context/navigation epoch。用户在等待 B 时已经转到 C，B 到达只能进入缓存或原任务提示，不能成为 current/旁文。答案抵达是例外中的明确异步事件，但也只更新问题状态，不夺取注意力。

### 10.2 Escape/关闭的层级

具体按键由手势设计决定，但关闭语义从最内层到最外层：

1. 关闭当前菜单/预览；
2. 收起未提交选择动作或问题编辑器（有文字时保留草稿）；
3. 取消未完成的连接第二端；
4. 关闭搜索/历史/归档/导入任务层；
5. 明确“收起旁读”才收起旁文；Back 仍按历史快照恢复。

关闭任何覆盖层都不删除持久 Question、Connection、Document 或 AnswerAssociation。

### 10.3 焦点与可访问反馈

- 覆盖层打开时焦点进入标题或首个输入；关闭后回到触发它的文档文字/动作。
- 加载和状态使用非阻塞 `role=status`；写入失败用 `role=alert`，但不自动把焦点从正文拖走。
- 键盘可以依次到达文档身份、连接标记、旁读、设为当前、问题标记和关闭动作；动作名称表达语义，不能只叫“打开”。
- 触摸没有 hover，因此“预览”通过一次轻触/聚焦出现，并继续提供显式“旁读”；不会把第一次触摸直接解释为提升当前。
- 窄屏可把 current 和旁文按顺序呈现，仍保留“旁读”“设为当前”“回到来源”三种语义。回答提示、搜索和编辑不能覆盖正文后无关闭路径。
- 减少动态效果时直接呈现最终状态；四种阅读意图及历史结果不变。

## 11. 实现契约与所需数据

### 11.1 推荐的意图事件

事件名可以调整，但 reducer/状态机必须能一一表达这些意图：

```ts
type ReadingIntent =
  | { type: "preview-target"; target: DocumentRef; cause: PreviewCause }
  | { type: "dismiss-preview" }
  | { type: "follow-connection"; connectionId: ConnectionId; from: AnchorRef }
  | { type: "promote-companion"; document: DocumentRef }
  | { type: "collapse-companion" }
  | { type: "navigate-search-match"; match: ExactSearchMatch }
  | { type: "ai-set-current"; target: DocumentRef; requestId: string }
  | { type: "answer-arrived"; arrival: AnswerArrival }
  | {
      type: "read-answer-beside-source";
      questionId: QuestionId;
      answerDocumentId: DocumentId;
    }
  | { type: "open-revision-beside-current"; revision: DocumentRef };
```

不要保留一个含义过载的 `open` 来处理所有情况。领域 `DocumentId/RevisionId/Anchor/Connection/Question` 与呈现实例 ID 仍然分开；阅读历史引用可恢复的语义目标，不把 DOM 节点或一次动画当身份。

### 11.2 现有能力可直接复用

- `DocumentBody/Passage` 的 Markdown 源偏移映射、原生选区和长正文虚拟化；
- `grep` 返回当前版本的精确 UTF-16 范围；
- `cat/open_document` 可读取指定不可变 revision；
- `ask`、`answer`、`link` 的独立持久实体；
- `history`、`archive`、`write/edit/mv/import_file` 及冲突检查；
- 目录的有界分页可为搜索元数据、边缘身份和归档覆盖层提供数据，但不得重新呈现成常驻目录。

### 11.3 必须补齐或明确的契约

1. Host 区分 `set_current` 与 `answer_arrived`；无归因的现有 `open_document` 保持 `set_current` 语义，`AnswerArrival` 必须带问题归因，避免两类意图互相吞并。
2. 会话可同时保存多个 `questionId` 的 awaiting/answered 状态，而非单一问题草稿。
3. 全局搜索结果显式携带用于命中的 revisionId；当前协议已有 summary revisionId，实现不得丢弃。
4. 关系/问题分页的“未加载”状态必须可表示；加载完成前不展示零关系结论。
5. 空间/手势组需提供语义动作入口：preview、follow、promote、close companion、back；视觉组需让 preview、current、companion、answer-unread 和 historical 清晰可区分。

## 12. 可验收的端到端场景

1. **预览不导航**：悬停 A 的连接目标 B，看到 B 标题、v1、关系和摘录；移开后一切消失，A 的 current、滚动和历史长度不变。
2. **沿连接旁读并提升**：从 A:v2 某段旁读 B:v1，A 保持 current；滚动 B 后明确提升，B 成 current；返回恢复 A/B 双方的版本、焦点和滚动。
3. **旁文文字可操作**：在 B 选择文字能提问或作为连接端点；单击/拖选正文不自动把 B 提升。
4. **提问分阶段恢复**：Question 保存成功但发送失败，来源出现已保存标记；重试后使用同一 questionId，不生成重复问题。
5. **答案不劫持阅读**：从 A 提问后转到 C 编辑；答案抵达时 C 和编辑草稿不动，只出现未读提示。选择“旁读答案”后恢复 A 的问题段落并在旁边显示回答。
6. **AI 设为当前会保全草稿**：用户要求 AI 打开 B，结果返回时正在 A 中输入问题；B 的导航已被接受，但 A 的草稿收成带来源的提示且全文不丢。返回 A 可继续编辑。若当时正在 IME composition，导航等 `compositionend` 才发生。
7. **回答与连接独立**：回答已关联但 link 失败，仍能旁读回答且界面写“暂无文字连接”，不画精确连接；重试 link 后才出现 beam。
8. **搜索定位精确版本**：查询词在 A:v3 多次出现，选第二处后打开 A:v3 并聚焦准确范围；即使 A 已有 v4，也不把 v3 偏移错误应用到 v4。返回恢复搜索前上下文和查询。
9. **长文档内查找**：目标段落最初未挂入 DOM；下一处仍能挂载对应块、滚动并高亮，不改变 current 或全局历史。
10. **编辑不迁移旧端点**：编辑 A:v3 保存 v4，页面显示 v4；连接仍指向 A:v3，界面给出查看旧端点入口，没有自动贴到相似句。
11. **并发编辑冲突**：另一个客户端先保存，当前保存失败；本地草稿完整保留，可查看最新版，系统不自动覆盖或悄悄合并。
12. **批量导入不中断阅读**：阅读 A 时导入三个文件，其中一个路径冲突；A 不变，两个成功项和一个可单独重试项清晰可见。
13. **归档仍可追溯**：归档 A 后当前页仍可读且标记归档；从 B 的旧连接仍能到达 A 的精确版本；恢复不新增 revision、不改变连接。
14. **异步乱序**：先搜索 q1 再 q2、先请求旁读 B 再转到 C；q1/B 晚到都不能覆盖 q2/C，只进入缓存或各自任务状态。
15. **窄屏、键盘和减少动态**：不使用悬停也能完成预览、旁读、提升、提问、读答案和返回；动作语义及历史结果与宽屏相同。

## 13. 需要实测的假设

- 预览中“标题 + 版本 + 关系 + 约 2–4 行摘录”是否足以让用户决定旁读；过少会增加误入，过多会遮挡正文。
- 答案抵达后默认只提醒是否让用户错过结果；测试来源问题标记与全局活动入口的发现率，不以自动切换 current 补救。
- 提升必须使用明确动作是否显得多一步；重点观察它换来的选字、滚动误触减少，而不是只统计点击数。
- 编辑保存后在同一页面切到最新版，是否比把新版放为旁文更符合“继续写”的预期；无论选择哪种，旧连接端点都不可迁移。
- 当前文档内字面查找与全空间区分大小写搜索的表述是否可理解；若用户持续期待不区分大小写，应修改服务端能力和文案，不在客户端伪造不完整结果。
