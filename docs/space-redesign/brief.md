# Xanadu Sidebranch：连续文档空间重新设计

## 用户这次纠正的核心

上一版把 3D 空间实现成打开若干文件的窗口管理器，用户明确否定这一前提。文档空间本来就包含全部文档。当前文档决定注意力中心和周边关系；关系较远的文档退到屏幕边缘，以露出边角、折页、叠放的形态保留存在感。用户不需要左侧文档目录、不需要打开/关闭文件的空间操作、不需要总览侧栏，也不需要阅读/总览模式开关。

用户要求从阅读者实际操作出发，分别深入设计空间组织、主要阅读流程、颜色和悬停动画、3D 手势和性能。先设计并统一契约，再实现，不把部署当作本阶段的目标。本轮明确不部署；当前线上版本不变。代码最终仍提交到 Sidebranch。

原有目标继续有效：网站公开介绍、单一所有者登录后浏览全部文档，ChatGPT App UI 划词提问；文档、问题、独立回答、回答关联、文字连接、不可变版本仍须分开。TXT/MD/PDF/文本统一进入文档系统。AI 可创建、搜索、定位修改、连接、设置当前文档。保留现有安全和持久化能力，不引入 Supabase。

## 已给定的概念，不从现成组件反推

- 文档属于持久空间，是否属于空间不由当前是否显示正文决定。
- 当前文档是注意力和导航位置。改变当前文档不创建或销毁文档，也不构成打开/关闭文件。
- 文档有版本；连接端点指向某个不可变版本的一段文字。文本相似不等于同一来源，不宣称已经实现 transclusion。
- 阅读时可以同时看见关联文字。展开程度、临时预览、文本位置属于呈现和交互状态，不等同于文档身份。
- 折页/叠放必须是可发现、可理解、可操作的空间呈现，不是用装饰隐藏一个普通列表。
- 所有文档逻辑上在空间里，不要求把所有正文、所有页和所有连接同时挂入 DOM。资源消费必须随当前可感知内容有界。
- 未加载关系不是不存在关系。不能用未知数据制造假的语义距离。

## 设计需要真正解决的难点

从 A 沿一处文字看 B，再转为阅读 B，A 的去处和回去方法是什么？没有连接的 C 怎样被发现？一百份同等相关的文档怎样折叠？边缘叠页拥挤时如何进入深处而不变成隐蔽侧栏？长标题怎样读，误触怎样避免，悬停何时只预览而何时改变当前文档？用户选择文字、滚动正文、移动空间时手势怎样避免争抢？动画被打断、指针离开、焦点切换、异步内容未返回时如何继续？窄屏、键盘、触摸、减少动态效果的用户如何完成相同语义操作？

要求每个设计决定落到具体用户行为和可观察结果。设计者可以提出并比较少量真正不同的策略，但须选出推荐方案并说明代价，不以“可选项列表”代替设计。不能依赖未来 AI 排序、自动语义聚类或臆造已有能力。

## 并行设计边界

1. spatial-model.md：文档全体的空间组织、关系距离与无关联文档、边缘折页与叠放、注意力迁移、需要的数据和程序实体。主导持久空间与局部呈现的边界，不负责定色值或输入键位。
2. reading-flow.md：从阅读者动作出发的连续流程（阅读、沿连接、选区提问、答案抵达、搜索定位、导入/创建/编辑、历史与归档），主要界面出现什么和什么时候出现。主导用户意图与反馈，不另造空间几何或手势映射。
3. visual-motion.md：视觉层级、纸页和折边、关系/选区/悬停/当前的颜色语义、字体、光影、动画前后状态/时间/中断与降级。以用户感知和可读性为依据，不把界面做成按钮工具栏，不替其它组定义导航语义。
4. gestures-performance.md：鼠标/触控板/触摸/键盘的输入归属、空间移动方式、原生文本操作、可中断过渡、性能预算与渲染路径。不要创建与空间模型不同的文档/导航状态。

根代理整合四份设计，明确跨界共享状态与冲突；设计阶段不改生产代码。实现按整合后的契约拆分，程序中的实体和关系须对应概念。可静态保证的性质由类型保证；测试只覆盖静态类型覆盖不到的风险，不镜像实现。

## 当前工程事实

主目录 `/workspace/sites/xanadu-sidebranch`，GitHub `JiaJunDeng5930/Sidebranch`。当前部署 v2，源代码本地 HEAD `3b75cab5c98f630ea436f4eb90d73a9a4cf225b1`。React/TypeScript + Sites Worker/D1/R2；官方 MCP Apps SDK。同一 Reader 运行在网站和 App。

当前 `lib/reader/scene.ts` 的 open/close view、read/overview、手动累计 views 应视为待替换设计，不是约束。`lib/reader/session.ts` 保存目录、草稿、关系投影、版本缓存。`components/reader/reader.tsx` 组合目录、场景、弹层和服务命令。`spatial-scene.tsx` 用 CSS 3D 纸页 + SVG 精确范围连接。`Passage` 和 `DocumentBody` 已实现 Markdown 源码偏移映射、原生选择、长正文虚拟化，可复用其可靠机制。

目录可分页加载所有元数据；`open_document` 当前只返回所定位文档的连接/问题页，不含全空间关系索引。后端文档、版本、锚点、连接、问题、回答关联已有独立实体和命令；新增只读空间索引应说明必要性与有界策略。现有单所有者鉴权不在空间重设计范围内；MCP 平台认证迁移见 ADR 0011。

已有参考资料在 `docs/xanadu-interaction.md`，其中窗口式方案已被用户这次纠正，不可当成新需求。原始出处包括 https://www.xanadu.net/XanaduSpace/btf.htm 与 https://xanadu.com/xUniverse-D6 。深入引用外部事实应核对原始来源。

基线：49 项测试和静态检查通过。旧版千节文档约 15,095 DOM / 577–618ms 长任务；v2 通过虚拟化显著减少正文 DOM。完整空间样本 260 文档/3篇千节长文/80连接，交互仍有约33ms帧间隔。必须针对新的实际操作取得测量，不能以单元测试通过或“用了GPU”作为性能达标依据。
